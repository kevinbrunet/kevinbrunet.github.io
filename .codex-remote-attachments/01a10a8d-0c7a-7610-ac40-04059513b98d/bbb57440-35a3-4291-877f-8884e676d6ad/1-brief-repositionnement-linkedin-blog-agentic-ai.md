## 1. Objectif

Repositionner le profil de Kévin Brunet autour de l'**ingénierie des
systèmes IA agentiques en production**, sans effacer son identité
d'architecte logiciel expérimenté.

Le repositionnement ne doit surtout pas raconter une « reconversion vers
l'IA » ni essayer de présenter Kévin comme un ML Engineer spécialisé
dans l'entraînement de modèles.

La trajectoire à rendre visible est plutôt :

> **Software Architecture → Distributed / Enterprise / Critical Systems
> → Agentic AI Systems → Reliability, Evals, Harnesses, Observability &
> AI Risk**

L'idée centrale est que Kévin travaille sur la couche d'ingénierie qui
transforme un LLM ou un modèle en **système logiciel exploitable,
observable, mesurable, gouvernable et fiable**.

## 6. Distinction importante entre Harness Engineering, LLMOps et AgentOps

Ne pas traiter ces termes comme des synonymes.

### Harness Engineering

Concerne principalement **le système qui entoure le modèle et organise
son travail** :

-   execution loop ;
-   context ;
-   tools ;
-   skills ;
-   memory ;
-   permissions ;
-   state ;
-   orchestration ;
-   validation ;
-   recovery ;
-   interfaces ;
-   sandbox ;
-   contrôles.

### LLMOps

Concerne davantage l'**industrialisation des modèles et applications
LLM** :

-   serving ;
-   versioning ;
-   deployment ;
-   routing ;
-   datasets ;
-   evaluation pipelines ;
-   monitoring ;
-   latency ;
-   costs ;
-   drift ;
-   CI/CD/CT.

### AgentOps

Étend cette logique au comportement d'un système agentique en
fonctionnement :

-   traces de trajectoires ;
-   tool calls ;
-   décisions ;
-   debugging ;
-   replay ;
-   evals ;
-   guardrails ;
-   coûts ;
-   latence ;
-   qualité ;
-   sécurité ;
-   comportement en production.

AgentOps est encore moins stabilisé lexicalement que LLMOps, mais le
terme apparaît déjà dans des intitulés d'emploi et dans des plateformes
spécialisées.

### AI Reliability / AI Systems Engineering

Ce sont les notions qui donnent le **sens global** au positionnement.

Le harness, les evals, AgentOps et LLMOps sont des moyens.

La finalité est :

> rendre un système probabiliste suffisamment observable, mesurable,
> contrôlable et robuste pour qu'une organisation puisse lui confier du
> travail réel.

## 14. Méthodologie en cours à valoriser

Kévin formalise une méthode de passage du prototype agentique à la
production.

Chaîne conceptuelle :

**Goal** → **Risk analysis** → **Expected behaviour** → **Test
strategy** → **Oracles** → **Evaluation dataset** → **Repeated runs /
statistical distribution** → **Acceptance thresholds** →
**Observability** → **Production monitoring** → **Failure analysis** →
**Controlled expansion of scope**

Cette démarche peut être décrite comme :

-   **Evaluation-driven agent engineering**
-   **Risk-driven agent engineering**
-   **Reliability engineering for agentic systems**

Ne pas inventer une norme ou présenter ces appellations comme des
standards établis.

Il s'agit d'un cadre de travail que Kévin construit à partir de
pratiques existantes.

> les contrôles, les évaluations, les frontières d'autorité et
> l'observabilité.**

Ne pas nécessairement reprendre textuellement ces phrases ; préserver
l'idée.
